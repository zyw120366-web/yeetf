# ye 每日执行

只在对应交易日收盘后运行。每日执行不得修改策略参数、ETF 池或成本。

1. 先读取 `results/live/account_state.json`。其中只能记录用户或券商明确确认的实盘资金、持仓与未完成订单；回测的 `signal_weights.csv`、模拟成交和影子持仓绝不能作为实盘仓位。再确认上一份订单计划的真实成交数量、成交价格和未完成数量；若上一份计划含买卖，写入 `results/live/YYYY-MM-DD_actual_fills.json` 并运行 `scripts/reconcile_actual_fills.py --date YYYY-MM-DD`。计划不能当作实际持仓，未对账时禁止新开仓。
2. 刷新日线并冻结当日盘面与资讯：

   ```powershell
   .\.venv-review\Scripts\python.exe scripts\fetch_prices.py --force
   .\.venv-review\Scripts\python.exe scripts\collect_daily_sentiment.py --date YYYY-MM-DD
   .\.venv-review\Scripts\python.exe scripts\export_sentiment_review_queue.py --date YYYY-MM-DD
   ```

3. 当前 Codex 对话逐条审核队列，用 `scripts/commit_manual_sentiment_review.py` 提交完整审核记录。ETF映射必须获得冻结文本中专属关键词直接支持；类别不能自动扩散到同类全部ETF。跨来源同公司仍逐行审核，系统在特征层自动只计一次。审核草稿同时记录模型家族、可见快照和使用界面。
4. 运行正式链路：

   ```powershell
   $env:PYTHONPATH='src'
   .\.venv-review\Scripts\python.exe scripts\run_after_close.py --date YYYY-MM-DD --skip-collect
   ```

5. 只有 `results/live/readiness_report.json` 为 `READY`，且 `live_account_state_confirmed=true`、`live_plan_uses_account_truth=true` 时，订单计划才可执行。计划位于 `results/live/YYYY-MM-DD_order_plan.json`；日报位于 `results/live/YYYY-MM-DD_daily_report.md`，并同步进入静态 HTML。日报必须逐层说明“51只全池（45核心冠军＋6挑战者空档补位）→基础筛选→核心优先→唯一目标”，标明每只ETF的池角色；若挑战者因核心候选存在而等待或让位，必须明确展示。
6. `results/audit/YYYY-MM-DD_run_manifest.json` 保存当日配置、代码、价格、审核、结果和页面的 SHA-256；`results/audit/YYYY-MM-DD_live_run_card.json` 汇总当日规则标识、计划、审核、放行与待确认事项，供日后逐文件复核。
7. ETF计划生成后，在15:00—15:30复核收盘宝是否已启用；对实际闲置现金按策略规则自动申报。记录实时年化、申报状态和异常；产品不可用时保持现金，不改动ETF计划。
8. 更新 `RESEARCH_STATUS.md` 和 `RESEARCH_MEMORY.md`，完成正式校验后检查 Git 差异与敏感信息。GitHub同步由Agent按改动重要性自主判断：正式日运行、规则/代码或账户真源等关键节点通常提交并推送，过程性研究无需单独推送；日运行提交信息使用 `daily: run YYYY-MM-DD close`。无差异时不制造空提交，是否同步及失败原因必须如实报告。

任一步失败都不得生成或执行部分买入计划。卖出风险信号不因情绪审核失败而失效。

月度消融和实盘复盘不属于上述流程，不得接入 `scripts/run_after_close.py`。
